# 决策记录: 迁移到寄存器式 ISA（三问 spike 已通过，分阶段实施）

Status: draft — 三个 spike 已实测（S1 收益上限 / S2 保护成本 / S3 语义安全网），
结论是「值得做」，但调用约定、寄存器压力与宏后端重写量尚未验证。

## 问题

四轮超级指令之后，`sum(2000)` 已从 305–351x 压到 111–118x（一轮循环 6 条 VM 指令 ≈ 66 ns/轮），
再往下走没有剩余空间：

- 第五轮回边融合（`INC_REG_JCC` / `INC_JMP`）把字节码从 40 条压到 34 条，**实测无收益**
  （`sum` 117.5x → 118.2x），已全量回退：每指令 ≈ 6 ns 里 dispatch 只占 2.3 ns，
  砍一条 dispatch ≈ 6%，落在轮间 3–4% 抖动里；
- 剩下的成本在**每条指令自己的活**上：栈式 ISA 每条指令都要 `PUSH/POP` 搬运操作数，
  handler 侧没有油水可刮（`dispatch 2.30 ns + handler 3.19–3.31 ns`）。

所以问题不再是「还能砍几条指令」，而是「**每条指令的工作量能不能降一个量级**」。
寄存器式 ISA 是唯一还能保住保护模型（字节码加密 + opcode 置换 + 间接派发）的路；
JIT/AOT 需要明文可执行页或原生产物，等于把保护丢掉，不在选项内。

## 提案

**分三阶段迁移到寄存器式 ISA**，每阶段独立可回退：

1. **阶段一：ISA 与算术子集**
   `r_dst = r_a op r_b` / `r_dst op= imm` / `CMP + JCC` / `JMP`，寄存器文件沿用现有
   `VmState` 的寄存器区；只覆盖整数算术与比较，结构体/切片/浮点继续用 `InputOffset` 路径。
2. **阶段二：保护 pass 重写 + 发射计数断言**
   MBA、`IncSubstitution`、`handler_mutation` 全部按寄存器形式重写（每个恒等式 4 条指令，
   见下「实测」），**同时**为每条 emit 路径加「发射条数断言」测试——漏接即红，
   不允许静默降级。
3. **阶段三：差分测试 + 全量切换**
   把 S3 骨架接到真实后端：现有栈式后端作左侧基准，新寄存器后端作右侧，
   用 `syn` AST 生成程序而不是玩具 IR。

### 实测依据（spike，`~/文档/rs-vm-spike-reg-isa/`）

同一台机器（i5-8265U、`taskset -c 6`、release），三组对照：

| 实现 | `sum(2000)` / 原生 | `fib(20)` / 原生 | 指令/轮 |
|---|---|---|---|
| 寄存器 VM（跳表分派，无解码） | 30.6–32.0x | 101–109x | 7 |
| 寄存器 VM（**表分派 + 置换解码 + 失败返回**，即 rs-vm 同条件） | **53.7x** | 168x | 7 |
| 当前栈式 rs-vm（融合指令跳过 MBA） | **116x** | 462x | 6 |
| 同上 + 完整 MBA 恒等式 | **82.0x** | — | 10 |

- **S1 收益上限**：同条件下 **2.85x（sum）/ 3.32x（fib）**，高于「值得重写」的 2x 门槛；
- **S2 保护成本**：MBA 恒等式在寄存器形式下只多 3 条指令（1.53x 开销），在栈式下要 ~12 条
  （`DUP;POP_REG;SWAP;DUP;POP_REG;AND;PUSH_IMM8;SHL;PUSH_REG;PUSH_REG;XOR;ADD`）——
  **保护代价从 12 条降到 4 条**。因此即便加上完整 MBA，寄存器版仍比现在跳过 MBA 的栈式快 **1.4x**；
- **S3 安全网**：20 万个随机程序 0 不一致（0.45 s，44 万程序/秒）；注入一条非交换 bug 后
  82% 用例变红，证明骨架能失败。

### 阶段一首批落地（2026-11-24）

新增 8 条寄存器式二元算术（base `0xA2`–`0xA9`）：`SUB` / `DIV` / `MOD` / `AND` / `OR` / `XOR` /
`SHL` / `SHR` 的 `*_REG_REG` 形态，等价于 `PUSH_REG a; PUSH_REG b; <OP>; POP_REG dst`，
栈中性、只置 ZF，除零/模零得 0，移位量按 64 取模——与栈式同名 handler 语义逐条对齐。

- 宏侧：`RegOp::from_binop` 覆盖 10 个算子，`can_expr_to_reg` 只在「有立即数形式」时才接受
  右侧字面量（目前只有 ADD/MUL），其余一律回退栈序列，绝不产生半截字节码；
- 实测（A/B，同探针同 seed、`taskset -c 6`、两版交替 3 轮）：`bitmix(2000)`
  **75.7–76.0x → 52.9–54.2x（−29%，1.42x）**；`arith` / `fib` / `sum` 在噪声内不变；
- 测试：`tests/register_isa.rs`（7 条，含除零/回绕/移位量 64/栈中性/与栈式逐对比对）、
  `tests/register_isa_macro.rs`（5 条，行为对齐）、宏侧字节码预算（自赋值 8 条 ≤90 字节，
  实测寄存器式 81 / 栈式 109）；门禁 **876 passed / 0 failed**。

### 阶段一次批：立即数形态（2026-11-24）

同一批 8 个算子补齐 `*_REG_IMM <reg:u8> <imm:u32>`（base `0xAA`–`0xB1`），等价
`PUSH_REG r; PUSH_IMM32 imm; <OP>; POP_REG r`。宏侧 `RegOp::has_imm_form` 全开，
右侧字面量不再回退栈序列（仍限 `u32` 范围）。

- 为什么先补它：实测字面量 RHS 比变量 RHS 贵 **1.5 倍**（`bitmix_imm` 79.6–82.0x vs
  `bitmix` 51.7–53.2x），而真实代码里 `x & 0xFF` / `x >> 8` / `i % 10` 是主流写法；
- 实测（A/B，两版交替 5 轮）：`bitmix_imm(2000)` **79.6–82.0x → 37.6–39.6x（−52%，2.1x）**；
- 其余场景落在历史噪声带内（`fib` 本次 402–443x，早前同版本曾出现 397x 的下沿），
  未观察到真实退化；`arith` / `sum` 基本不变；
- 测试：`tests/register_isa.rs` 增至 11 条（新增立即数 4 组：回绕、除零/模零、位运算、
  移位量 64、与栈式逐个比对）；门禁见提交信息。

### S3-real：差分骨架接到真实后端（2026-11-24）

玩具 IR 的差分只证明了方法可行。真实版放在 `tests/fused_differential.rs`：
每个 `#[vm_protect]` 函数配一个**语义契约相同**的原生孪生体，用确定性随机语料逐值比对。

- 语料：14 个边界值（0/1/2 的幂/63/64/65/255/256/`u64::MAX`）+ 全空间随机，20 000 组/函数；
- oracle 是 **VM 契约**（整数回绕、除零/模零得 0、移位量按 64 取模），不是 Rust 语义；
- 覆盖面刻意打满：`d_imm_each` 让 8 条 `*_REG_IMM` 各自都有字面量 RHS，
  `d_bits` / `d_shift` / `d_loop` 覆盖寄存器形态与循环；
- **变异自检**：把 `handle_xor_reg_imm` 临时写成 `a & b` → 用例变红（左 5140 / 右 43690），
  改回即绿。第一版语料没覆盖到这条立即数指令，变异全绿——补 `d_imm_each` 后才抓住，
  说明「变异自检」不是形式主义，它能发现语料的漏洞。

同时补了构建期校验：`build.rs` 现在也比对 `vendor/aegis_vm_macro/src/opcodes.rs` 的常量
（原来只校验 `crypto.rs`），三份副本任一错位都在构建时失败。

### 阶段一三批：条件融合（2026-11-24）

先量了指令构成再决定补什么（临时插桩 `dispatch_indirect` 统计 base opcode，测完撤销）：
纯标量循环 / 数组读写 / 带分支三种负载下，**栈搬运占 41.7% / 62.2% / 50.0%**，算术只占
8.3% / 21.2% / 21.0%，`if` 条件物化（`DUP; PUSH_IMM8 0; XOR; DROP`）与数组寻址是两个最大头。
所以三批不补算术，改补条件。

- 新增 `CMP_REG_IMM_JCC <a:u8> <imm:u32> <cond:u8> <offset:i16>`（base `0xB2`），等价
  `PUSH_REG a; PUSH_IMM32 imm; CMP; DROP; DROP; Jcc cond`；`imm = 0` 即零值测试；
- 宏侧把「条件为假则跳」统一成 `emit_falsy_cond_jump`：寄存器-寄存器、寄存器-立即数
  （左侧是可编成寄存器的表达式就先算进临时槽）、裸变量（零值测试）三种形态，
  编不了才回退栈序列。`if` 与 `while` 都走这条路；
- 实测（A/B 4 轮交替）：`branchy(1000)`（循环内 `if i % 2 == 0`）
  **404.7–459.7x → 226.5–232.4x（−45%，1.8x）**；其余场景在噪声内；
- 测试：`tests/register_isa.rs` 15 条（+4 组：六个条件码、零值测试、栈中性、与栈式逐个比对）、
  `tests/fused_differential.rs` 9 条（新增 `d_branch`：立即数边界 / 变量-变量 / 零值测试，2 000 组）；
  门禁 893 passed / 0 failed。

### 顺带发现的既有 bug（未修，需单独立项）

测量用的基线在 `branchy(2000)` 上报 `E04`（InvalidRegister，实为 `E03` StackOverflow）。
最小复现：`while` 循环体里的 `if`，条件走**回退路径**（例如 `if 0 == i % 2`，字面量在左）时，
每执行一次漏一个栈槽，约 1000 轮后溢出；`if 36` 次则看不出问题。

- 与本轮改动无关：用改动前的提交同样可复现；
- 条件能被融合（寄存器/立即数形态）时不复现——融合指令是栈中性的；
- 影响：任何「循环里带 `if`」且条件编不进融合的受保护函数，在迭代数大时会静默失败于 E03/E04；
- 待办：定位 `compile_expr` 在比较形态下的栈净效果与 `compile_if` 回退序列是否各少算一次，
  修好后把上面的复现变成回归测试。

## 备选方案

- **继续铺超级指令**：已到顶。第五轮回边融合把字节码真实压短了 6 条，A/B 无收益，
  说明瓶颈已从「指令条数」转到「每条指令的工作量」，继续融合只能得到个位数百分比。
- **JIT / AOT**：收益最高（~10–20x），但运行时 JIT 需要 W^X 可执行页（攻击者可直接 dump
  明文机器码），AOT 产物是原生码（虚拟化保护整体消失）。除非产品定位改成「不做保护」，否则不做。
- **一次性全量重写**：3–6 周主线冻结、保护 pass 与 800 个测试同时失效、失败时无法回退到可用状态。
  落选理由：把可行性风险与工期风险叠在一起，而 S1–S3 已经允许把它拆成每阶段可独立验证的三步。
- **保持现状（停 116x）**：成本最低，但放弃了 1.4–2.8x 的实测空间，且保护强度在融合指令上
  本来就有缺口（新 opcode 跳过 `IncSubstitution` 与 `handler_mutation`），不迁移也不能补。
- **in-tree 双后端并存**：宏与上游彻底分叉、维护两套 handler 与两套测试，收益只有过渡期方便。
  落选理由：S3 的差分骨架已经能在分支里完成同样的事，不需要长期并存。

## 验收标准

全部为机器快慢无关的判据：

1. **性能**：目标函数（`sum(2000)`、迭代 `fib(20)`）在**同等保护强度**下比当前栈式快 **≥1.3x**；
   保护强度等级必须在决议里写明（MBA 覆盖哪些算子、替换是否开启），不许拿「跳过保护」的
   旧数字对比「带保护」的新数字。
2. **语义**：差分测试 ≥200 000 个程序 0 不一致；注入一条非交换 bug 必须变红。
3. **保护不降级**：每条 emit 路径都有「发射条数断言」测试，漏接 MBA/替换即红；
   现存的「融合指令跳过 `IncSubstitution`」缺口必须在阶段二一并补上，不许带着走。
4. **门禁**：`./scripts/check.sh` 通过（clippy `--all-targets -D warnings`、全量测试、文档门禁）；
   现有 800+ 测试中凡是断言**具体字节码序列**的，改写为断言**语义/结果**，不许删除覆盖面。
5. **向后兼容**：旧字节码（含已发布版本加密产物）必须仍可执行，否则需在决议里写明版本边界。

## 风险

- **R1 保护静默降级（最严重）**：MBA / `IncSubstitution` / `handler_mutation` 全部依赖栈式形态，
  迁移时必须整体重写；漏掉任一条 emit 路径，测试仍然全绿，但保护已经消失。缓解：发射计数断言，
  且断言须能「关掉即变红」地自证。
- **R2 寄存器压力**：现设计寄存器上限 248 且没有值栈兜底；S1/S2 只用了 3–8 个寄存器，
  深层表达式必然需要 spill。缓解：阶段一就实现「寄存器 + spill 槽」混合，并重设调用约定。
- **R3 现有测试失效**：手写栈字节码的测试（`tests/fused_opcodes.rs` 等）在寄存器形态下无意义。
  缓解：S3 的差分骨架 + 把断言从「字节码序列」改为「执行结果」。
- **R4 宏与上游分叉**：`vendor/aegis_vm_macro` 一旦改后端，就与上游再无可合并性。
  缓解：分支隔离，不做 in-tree 双后端；迁移完成前上游同步冻结。
- **R5 保护不透明性下降**：寄存器数据流比栈式显式，第三方 devirtualizer 更容易跟。
  缓解：MBA 覆盖面不降级，并在阶段二补上融合指令缺失的替换变换。
- **R6 工期与沉没成本**：若阶段一实测不足 1.3x，必须立刻停，不许「再改改看」。
  缓解：阶段一结束即用同一套 AB 探针复核，判据前置写死。
- **已放弃的东西**：`no_std` 路径的寄存器文件必须仍是 `alloc` 数组（不得引入 std）；
  `CMP` 的 pop/pop/push/push 契约将被新 ISA 的新指令取代，属于 ISA 层面的破坏性变更，
  需在阶段一写明旧 opcode 的保留期。
