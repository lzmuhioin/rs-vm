# 决策记录: 栈式 ISA 效率优化试验收口（结果并入 `main`）

Status: accepted — `feat/stack-isa-opt` 自 `main` `b17c9a9` 分叉、37 个提交后收口并入 `main`：
真实形态负载每迭代耗时降 **45%–55%**（ABBA 五轮交替中位数），`locals_heavy` 栈搬运条数 −47%，
并修掉一个既有栈泄漏缺陷（四个负载此前根本跑不完）。第三层（栈顶缓存、局部变量直接寻址）不在本轮范围。

## 问题

栈式 ISA 是 `main` 的稳定实现，但每迭代指令数远高于原生：动态剖析实测栈搬运占 50.8%、
混淆注入占 20.8%、真实计算只占 21.5%。寄存器 ISA 分支（`feat/reg-isa-stage1`）已证明可把倍率降到
Standard ≈470x，但它形态变更大、改变解密后指令流的可读性、且融合指令带来新的保护缺口，
不宜作为主线。

本试验要回答的问题是：**在不动 ISA 形态、不扩大保护缺口的前提下，栈式 ISA 靠编译器侧改动
还能拿到多少可重复的收益**——若拿不到两位数改善，就按「维持现状」收口。

## 决策

**1. 三层优化按「风险递增」推进，只做前两层与部分第三层。**

- 第一层（窥孔，零语义风险）：`PUSH;POP` 空转、`POP_REG;PUSH_REG` 直传、`DROP;DROP` 合并。
- 第二层（超指令，只走末尾追加）：`XOR_REG_REG`、`SHR_REG_IMM`、`XOR_REG_IMM`、
  `AND_REG_REG`、`AND_REG_IMM`、`NATIVE_READ_REG` 六条。
- 第三层（结构性，只做无风险部分）：临时寄存器池 `RegPool`（`248..=255`，`Drop` 自动归还）、
  语句级「值被丢弃」路径、赋值右侧 `try_expr_to_reg` 全或无快路径。

**2. `let` 初始化走寄存器（M4）被实测否决并整段回退**（`77bf8c7`）。它在计数负载上只降 1.75%
（落在 ±15% 注入噪声带内），却让 `benches/vm_workloads.rs` 的 `arith` 真实形状负载算出 0。
收益不可测、风险只在真实代码里发作，这笔账永远亏。

**3. 栈顶缓存与局部变量直接寻址不做。** 它们改变求值模型，属重写级；本轮目标是验证「测量—改动—复测」
闭环是否成立，不是追最终解。剩余 44.8% 的栈搬运要动它们，须另立决议。

**4. 顺带修掉一个既有栈泄漏缺陷。** `compile_eq` / `compile_ne` / `method.rs::is_empty()` 用 `XOR`
判相等（`a^b==0` 即相等），但 `XOR` 弹 2 **压回 1**，那个异或结果是死值没人丢 ⇒ 一次比较净栈 +2
而调用约定只要 +1。放进循环体就逐轮累加。修法：`emit_xor()` 后补 `emit_drop()`（`DROP` 不动标志位）。
`LT/LE/GT/GE` 从来没事，因为它们用 `CMP`（弹出来又压回，需两次 `DROP`）。

**5. 把「编译期栈平衡断言」固化进编译器**（`compiler/stackcheck.rs`），防止同类缺陷复发：
在 `emit_op` 按 base opcode 的栈效果推进栈深，跳转登记目标标签的期望深度、`mark_label` 时比对
（循环回边因此当场现形），`compile_expr` 外包一层「必须净 +1」的契约检查，函数末尾校验返回值约定。
`AEGIS_STKCHECK=1` 才把失衡报成编译错误；记账本身常开且不改变生成的字节码。

## 备选方案

- **直接做栈顶缓存（跳过窥孔）**：收益可能更大，但改变求值模型、实现与调试成本高，一旦失败会污染
  整条分支；且无法回答「测量闭环是否成立」这个前置问题。已弃。
- **在栈式 ISA 上做寄存器分配器**：这是最终解（可吃掉剩余 44.8% 搬运与复合赋值开销），但它同时重写
  表达式求值、变量访问与调用约定，属重写级项目，不宜与「试验可行性」混在一轮。留待单独决议。
- **维持现状不优化**：若两轮内拿不到可重复的两位数改善就回退到此项。**实际结果远超这条止损线**，
  故不采用。
- **把寄存器 ISA 分支直接合入主线**：形态变更大、保护特征改变、缺口需持续盯防；本试验证明栈式 ISA
  在不动形态的前提下已能拿到同等量级的改善，故继续保持其为对照与备选，不并入。

## 后果

**端到端（`benches/vm_workloads.rs`，`taskset -c 6`，五轮 A,B,B,A 交替，取中位数）**

| 负载 | 基线倍率 | 当前倍率 | 每迭代耗时变化 |
|---|---|---|---|
| `arith` | 291.8x | 140.4x | **−51.3%** |
| `bitmix` | 173.0x | 94.7x | **−45.3%** |
| `sum` | 159.6x | 71.5x | **−55.3%** |
| `branchy` | 跑不完（`E04: E03`） | 228.3x | 从崩溃到可跑 |
| `arrloop` | 跑不完 | 118.8x | 同上 |
| `writeback` | 跑不完 | 268.0x | 同上 |
| `fib` | 跑不完 | 248.8x | 同上 |

**动态剖面（`prof_split`，100 次调用，两侧负载代码逐字节相同）**

| 负载 | 条/次 | 搬运/次 | 搬运占比 |
|---|---|---|---|
| `expr_only` | 31 → 25（−19.4%） | 14 → 11 | 45.2% → 44.0% |
| `locals_heavy` | 331 → 209（−36.9%） | 194 → 102（**−47.4%**） | 58.6% → **48.8%** |
| `mixed` | 324 → 241（−25.6%） | 181 → 108（−40.3%） | 55.9% → **44.8%** |

**栈泄漏修复的量化**（`AEGIS_STKPROBE=1`，n=300 最大栈深）：`b_two_way` 303 → 3、
`a_three_way` 453 → 4、`c_two_independent` 603 → 3、`g_eq_one` 304 → 4，循环体无 `if` 的对照组
恒定 2。`tests/stack_leak_probe.rs` 的三个 `#[ignore]` 已去掉，n=1000 不再撞栈上限。

**测量口径的两个已知瑕疵（据实记录）**

1. **时间基线不能取 `main`**：`benches/vm_workloads.rs` 是本分支在 `b2cfa47` 才引入的，`main` 上
   没有该 bench。时间基线因此取 `b2cfa47`（测量工具刚落地、优化未开始），并把当前分支的 bench
   源码逐字节复制过去（`diff -q` 已证相同）。
2. **条数基线晚了一个提交**：`b2cfa47` 上还没有 `prof` 特性，`--features prof` 直接报
   `the package 'aegis_vm' does not contain this feature: prof`。条数基线改用 `2bbe959`
   （`prof` 已落地、第一处代码优化 `ed3ee14` 尚未开始），两侧 `prof_split.rs` 的负载代码逐字节相同。
   两者之间只隔工具与文档提交，不含优化代码，故不影响结论；但严格说两组数字不是同一次构建。

**代价与遗留**

- 每一轮改动都改变了字节长度，而注入层注入点由 `bytecode.len()` 决定 ⇒ 指令计数整片漂移，
  分辨率下限约 ±15%。**只有差异远大于噪声时才敢归因**，小改动一律用端到端 ABBA。
- 剩余栈搬运 44.8% 集中在「表达式中间值压栈」与「循环变量读写往返」，要吃它得上栈顶缓存或
  局部变量直接寻址，属重写级，需单独立决议。
- 诊断工具已固化（`AEGIS_DUMP` 最终镜像反汇编 + 覆盖度自检、`AEGIS_NOJUNK`、`AEGIS_STKPROBE`、
  `AEGIS_TRACEALL`、`AEGIS_RING`、`AEGIS_STKCHECK`），后续同类问题不必重新造轮子。
